### Findings

#### [IMPORTANT] Rate limiting is per function instance, so the durable floor on confirmation mail is a 2-minute cooldown (30 mails/hour to any address)

- **Location:** `/Users/eric/conductor/workspaces/hasToggle.dev/ljubljana/apps/web/lib/rate-limit.ts:31-69,105-118`; `/Users/eric/conductor/workspaces/hasToggle.dev/ljubljana/apps/web/app/api/confirm/route.ts:24,30-31,244`; `/Users/eric/conductor/workspaces/hasToggle.dev/ljubljana/apps/web/app/[locale]/contact/actions/contact.tsx:18,38-45`
- **Description:** With no Upstash in prod, `rateLimiter()` returns `createMemoryLimiter`, a `Map` that lives in one function instance. Vercel scales instances on concurrency and recycles them, so every parallel instance grants its own `PER_ADDRESS` (3/h) and `PER_CALLER` (10/10min) budget, and a cold start zeroes it. The only cross-instance control on `/api/confirm` is the Mongo-backed `RESEND_COOLDOWN_MS` at line 244, which is 2 minutes and never grows. The contact action has no durable control at all.
- **Impact:** (a) Mail bombing: an attacker submits a victim's address every ~2 minutes and the victim receives up to 30 "confirm your subscription" mails an hour, 720 a day, indefinitely, each from `RESEND_FROM`. That burns Resend quota and, once the victim hits "spam", the sending domain's reputation. (b) The contact form can be looped at roughly 3 × (number of warm instances) per hour into the `RESEND_FROM` inbox. (c) The already-subscribed path is bounded (idempotency key per day) — that one is fine.
- **Proof of concept:** A script POSTing `{"email":"&lt;victim&gt;"}` to `/api/confirm` once every 121 s from a single IP. The memory limiter will trip after 3 hits per instance, but concurrent requests from a second IP (or a burst that forces a new instance) get fresh budgets; the cooldown line is the only thing that always holds, and it allows a send every 2 minutes.
- **Recommendation:** Persist the per-address budget in the store you already have. Cheapest shape: store `confirmationsSentToday`/`lastConfirmationAt` on the subscriber row (they are written in the same `updateOne`) and refuse — silently, keeping the uniform `SUCCESS_MESSAGE` — when the daily count is over a small cap (e.g. 5), or make the cooldown exponential (`2min, 10min, 1h, 24h`). For the per-caller limit, either a `rate_limits` collection with a TTL index keyed on `prefix:ip`, or a Vercel WAF rate-limit rule on `/api/confirm` and on POSTs to `/contact`, which needs no code and is the layer `lib/rate-limit.ts`'s own comment says is the real tool. Until one of those lands, treat `PER_CALLER` as a burst limiter only, as the file comment already admits.

#### [IMPORTANT] `/api/og` renders a fresh PNG for every distinct `title` with no throttle

- **Location:** `/Users/eric/conductor/workspaces/hasToggle.dev/ljubljana/apps/web/app/api/og/route.tsx:53-55,203-205`; `/Users/eric/conductor/workspaces/hasToggle.dev/ljubljana/apps/web/app/api/og/title.ts:11-23`

#### [SUGGESTION] `/api/confirm` accepts cross-site `text/plain` form posts, which lets a third-party page borrow visitors' IPs against the caller limit

### Positive Observations

Verified against the code, not assumed:

- **Webhook signature:** `resend.webhooks.verify` (resend 6.28.1) delegates to `standardwebhooks`, which enforces the timestamp tolerance and constant-time HMAC compare; the secret is required (`startsWith("whsec_")`) so a missing secret fails closed. Body is read as text before parsing.
- **Reconcile auth:** `timingSafeEqual` with length guard, secret required at ≥32 chars, response is counts only, and `orphansLookWrong` refuses a listing that would empty the list.
- **Tokens:** 256 bits from `crypto.randomBytes`, only the SHA-256 hash is stored, 24 h expiry, Resend idempotency key derived from the hash so a retry cannot double-send.
- **Confirmation origin:** the `Host`-derived origin is honoured only for the configured URL, `VERCEL_URL`/`VERCEL_BRANCH_URL`, or localhost — a spoofed Host cannot make the confirm link point at an attacker's domain. `Location: /confirmed` is relative: no open redirect.
- **Mongo:** `normalizeEmail` collapses non-strings to `""`, `searchParams.get` is always a string, webhook payloads are signature-gated; every filter is a string or a static shape. No operator injection path found.
- **Enumeration:** uniform `SUCCESS_MESSAGE` for new, pending and already-confirmed addresses; rejection reasons for disposable/undeliverable share one line.
- **Server actions:** Next's Origin/Host comparison (docs: `data-security.md:550`) covers CSRF for `contact`, `pressTheButton`, `rebakeShell`; `contact` uses a zod schema, a fixed `to`, and React-escaped templates; the cookie in the mutation demo is `httpOnly`, `SameSite=Lax`, and parsed with `/^\d{1,4}$/`.
- **Headers:** HSTS 2y + subdomains, `frame-ancestors 'none'` + `X-Frame-Options: DENY`, COOP/CORP same-origin, `object-src 'none'`, `base-uri 'none'`, `form-action 'self'`, strict referrer. `'unsafe-inline'` in `script-src` is a documented trade for the static shell, and the compensating fact holds: the only `dangerouslySetInnerHTML` sites (`code-block.tsx:46`, `replay-code.tsx:29`) render Shiki output of repo-owned strings; no visitor input is ever rendered into HTML.
- **Env:** `client: {}` in `env.ts`; every `NEXT_PUBLIC_*` in the extended keys is a public identifier (PostHog key/host, GA id, Sentry DSN, URLs). Secrets are server-only and validated at boot. Sentry has `maskAllText`, `blockAllMedia`, and no `sendDefaultPii`.
- **OG input:** `clampTitle` strips `\p{Cc}\p{Cf}` and caps length; fonts are read once per instance from a fixed path — no path or URL is attacker-influenced, so no SSRF or traversal.
- **Errors:** `error.tsx` shows a fixed line; API 500s return fixed JSON; `SyntaxError` on bad JSON is mapped to a 400 without echo.
