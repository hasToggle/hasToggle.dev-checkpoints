The title (and the structure of our demo) about the four eras is not quite on point. The masterclass is about agentic engineering. Let me explain. Agentic engineering is something we arrived at. It not something that was possible and not something people wanted four years ago. Hence, my approach to a presentation about the stage/era we're in now and call "agentic engineering" is to recount lived experience against the historic background of how AI developed and how engineers had to shift their mindset. The first "era" in the demo serves the purpose of rooting the entire knoweldge of LLMs in the completion mechanism. It was not a time where engineers actually used GPT 2 for work. It was not useful, yet. And OpenAI knew this, too. They saw that you could extract information from the model if you learned how to prompt it, which was prior to the Q&A format. A completion just continued the question instead of answering it, as our demo shows. Because it was hard to extract knowledge from the model, OpenAI posttrained the model on the Q&A format (verify this using web search, please). That was the moment of ChatGPT. Suddenly, the model was useful. It wasn't useful for engineering work, yet. But you could extract knowledge more readily, more easily. As the models improved and reasoning was added as way for the model to use multiple steps as a way of thinking to arrive at the answer and as these reasoning-capable models got better at reasoning then they became barely useful for engineering work, like completing a function signature and body given a comment that describes what the function should do. That's what I want to focus on in era 2. The "let me ask ChatGPT and copy/paste the answer over to my coding editor" era. The Cursor era where developers could select portion of their code to provide it as context for the integrated chat interface on the right. No more copy/paste from ChatGPT, so it feels less fragmented as an experience. That's why Cursor was so successful as an editor that was forked off an open source VS Code codebase. VS Code couldn't do it because it needed substantial refactoring; it was very hard to do this kind of editing from a chat interface because these things were bolted on top instead of integrated into how the editor works (verify this as well).

But every little change, the Q&A format, the model's baseline improvement, the reasoning capability, the multi-modal capability (do you even remember when a model couldn't understand image?), the chat-like experience from ChatGPT integrated into the coding editor itself, all these things were shaped by what the model could barely do and by how people learned to use it.

And mind you, at that time of Cursor as an AI-driven chat editor if you will, the amount of work and the quality of work you could do with it was minor. A senior engineer was faster and better. With AI you would produce code that had to be corrected, rewritten, refactored because it neglected the surrounding context, it missed basic working of the framework the code was written in (like react functional components and their lifecycle). It was more work to correct what the LLM generated to fast, than to write it yourself.

That changed.

People started experimenting with agents. And as always there was a debate about what an agent is. Various definitions by various people. Leaving aside the interpretation of what an agent is, mechanistically an agent was an LLM with tools, trapped in a loop. You would chat with the LLM, the LLM would think, sometimes it would invoke its tools like read this file, write this file, and return a response. This was the beginning of agentic engineering, the era 3 of the masterclass. This is when the product Claude Code was launched. Anthropic has the most capable coding models already. If you were not using the Sonnet and Opus models you were not doing any meaningful work. When Claude Code launched, it was once again barely useful. Even with the very models that were the most capable at coding tasks the harness around it made the product just barely useful. It was different, too. Cursor was the UI. Claude Code was the terminal. That does not attract the same kind of people. But Anthropic chose the terminal because that was the common denominator among their own employees, some developers, some researchers, some marketing people, etc. Designing an interface that works for everyone is not something you could reasonably start with. But the terminal, no need to worry about the UI, you have a similar chat-like experience just not in the browser or your familiar coding editor, but you could chat with it and it would use its tools to do work.

As the models improved, the work you could do in Claude Code got more sophisticated. You could have the agent do more high quality work, touch more files without introducing breaking changes, and code for longer. The models became increasingly more capable of these long horizon tasks where an agent would run for tens of minutes at first, then for hours.

That's where the subscription comes in. It's very expensive to code with Anthropic's models. If I had to pay via their API it would cost several thousand Euros every month. But with the subscription you only pay a flat 180 Euros a month. You get a quota that you can use. And if you use up all of it, you have to wait. That's why I have an automated morning greeting to the LLM so the window starts early. I can burn through my limit in 3h and I'd have to wait for 2h.
