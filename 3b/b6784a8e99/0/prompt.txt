## 2. Ingestion / capture paths

Three real paths, one env-config-gated.

1. **Manual note** — `app/actions/knowledge/create-source.ts` → `createManualSource(text)`. Inserts `{type:"manual", status:"received", tenantId: orgId}` into `sources`, then `after(() =&gt; processSourceNow(...))`. UI: `components/brain/note-form.tsx`.
2. **Voice memo** — `components/brain/recorder.tsx` (MediaRecorder) → `uploadPresigned` to a **private** Vercel Blob via `app/api/knowledge/upload/route.ts` (token scoped to `voice/&lt;name&gt;`, audio-only content types, 100 MB, 10 min TTL) → `createVoiceSource(blobUrl, contentType)` validates the host against `PRIVATE_BLOB_HOST_REGEX` and inserts `{type:"voice", audio:{blobUrl}}`. Format helpers in `lib/capture.ts`.
3. **Inbound email** — `apps/api/app/webhooks/inbound-email/route.ts`. Resend/svix signature verify → `parseInboundSenderMap(process.env.KNOWLEDGE_INBOUND_SENDERS)` → `createEmailSource` (`packages/knowledge/inbound.ts`, deterministic `_id` so retries are no-ops) → `after(() =&gt; processSource(...))`.

Both instant legs converge on `apps/app/lib/instant-pipeline.ts` → `processSource` from `@repo/knowledge`, with the 5-minute cron as backstop.

**Proposals** are never created by the app. They are created inside `@repo/knowledge` only: `extraction-run.ts` / `process-source.ts` (from sources), `re-extraction.ts` (user-triggered retry), `consolidation.ts` and `contradiction.ts` (cron-triggered, source-less proposals).

**Meeting / calendar integration: none. Not real, not stubbed.** Grepping `calendar|meeting|zoom|granola|gcal|otter|fireflies` across `apps/app`, `apps/api`, `packages/knowledge` returns only German fixture text and one comment. `components/brain/brief-pane.tsx:15` says it out loud: *"This is that, **with the calendar left out**."* The `/` layout's pitch copy and the brief pane are both built to the shape of a pre-call trigger that has no trigger.

**Flag — email tenancy is env config.** `KNOWLEDGE_INBOUND_SENDERS` is a hand-maintained JSON blob mapping `sender-email → tenantId`, read from `process.env` per request. There is no per-org inbound address, no UI to manage it, no relationship to the `organization` table. Onboarding an org to email capture requires a deploy. Everyone not in the map is logged and dropped (`route.ts:~120`).

## 4. Ask / answer flow

- **Agent**: `apps/app/agent/agent.ts` — a three-line `defineAgent({ model: process.env.KNOWLEDGE_CHAT_MODEL ?? "deepseek/deepseek-v4-flash-0731" })`. Behaviour lives entirely in `agent/instructions.md` (two-tier facts-vs-raw-sources doctrine, mandatory citation, conflict surfacing, abstention, prompt-injection handling).
- **Mount**: `withEve(...)` in `apps/app/next.config.ts` mounts `./agent` at `/eve/v1/*`, same-origin — no separate service, no CORS, no second token.
- **Channel/auth**: `agent/channels/eve.ts`. Verifier chain `[betterAuthSession, evalTenant, localDev()]`. `betterAuthSession` re-reads the session off request headers and stamps `attributes.tenantId = session.session.activeOrganizationId`; returns `null` (falls through, does not accept) when there's no active org.
- **Tools**: `agent/tools/search-knowledge.ts` (hybrid `retrieveFacts` + optional Voyage rerank + `findContestedFactIds`), `agent/tools/search-sources.ts` (raw unreviewed material). Both read `tenantId` from `ctx.session.auth.current?.attributes?.tenantId` and throw if absent — never from tool input.
- **Client**: `components/brain/knowledge-chat.tsx` calls **`useEveAgent()` with no options at all**. Per `node_modules/eve/dist/src/react/use-eve-agent.d.ts`, that means: default same-origin host, default reducer, **no `session`, no `initialSession`, no `initialEvents`**. The store (`eve-agent-store.js`) creates the session lazily on first `send()`.

**Sessions are per component mount, not per user or per org.** Nothing keys, stores, or reloads a session id. A page refresh or a tab-switch away from the Ask pane and back starts a brand-new conversation. There is no history surface.

**Receipts** travel out-of-band, deliberately: `app/actions/knowledge/get-receipts.ts` (server action) is called on first citation click by `components/brain/use-receipts.ts`, composes via `composeReceipt` + `findContestedFactIds`, resolves capturer names via `lib/member-names.ts`. Rendered by `receipt-panel.tsx` / `citation-chip.tsx` / `fact-citation.tsx` / `source-citation.tsx`. **Nothing about an answer, its citations, or its receipts is persisted.** Receipts live in a `useState` map for the life of the mount.

**Flag — known auth hole, documented and unfixed.** `agent/channels/eve.ts:88-90`:
&gt; *"route auth authenticates the caller, it does not prove that this caller owns the session id in the URL. eve treats a session id as a bearer capability, so before this is exposed beyond internal users we need to persist session → tenant ownership and check it on resume and on stream."*

## 6. Tenancy

`tenantId` is always the better-auth **active organization id**, but it is derived **three independent times**:

1. **Server actions / pages** — `auth()` from `packages/auth/server.ts` returns `orgId = session.session.activeOrganizationId`. Every knowledge action opens with `const { orgId } = await auth(); if (!orgId) return &lt;empty&gt;;` and then puts `tenantId: orgId` **inside the Mongo filter itself**, not as a post-hoc check. This is consistent across all 10 knowledge actions. `re-extract.ts` documents the pattern explicitly ("a proposal id from another tenant simply does not match and looks identical to 'not found'").
2. **Agent channel** — `agent/channels/eve.ts` re-reads the session from raw request headers via `authInstance.api.getSession()` and stamps `attributes.tenantId`. Tools read it back off `ctx.session.auth`. This path shares no code with (1).
3. **Evals** — `evalTenant()` reads `process.env.EVAL_TENANT_ID`, gated on `isLocalDevelopmentServer()`. Ordering (`evalTenant` before `localDev()`) is pinned by `__tests__/eval-tenant.test.ts` because `localDev()` would otherwise shadow it.

Storage is also split: the auth/app DB (`@repo/database`, `MONGODB_DB ?? "app"`) is a **different Mongo client and database** from the knowledge DB (`packages/knowledge/client.ts`, `KNOWLEDGE_MONGODB_URI` / `KNOWLEDGE_MONGODB_DB ?? "knowledge"`). There is no FK, no join, and no referential integrity between `organization` in one and `tenantId` strings in the other. Cross-DB reads happen ad hoc — e.g. `get-receipts.ts` calls `listOrganizationMembers(orgId)` (auth DB) to resolve `capturedBy` on knowledge documents.

Vector/text index tenancy is enforced as a **pre-filter** in `packages/knowledge/retrieval.ts` (`{ path: "tenantId", type: "filter" }`) — noted in-file as deliberate, since post-filtering would let another tenant's docs consume this tenant's `k`.

## 7. Anything file-based

Almost nothing, and nothing product-facing.

- **Fixture corpus**: `packages/knowledge/fixtures/{corpus,facts,sources,ids}.ts` — ~80 hand-authored German facts and ~35 sources, as TypeScript literals.
- **Seeding**: `packages/knowledge/scripts/seed-evals.ts` (+ `.cli.ts`) wipes and reinserts those fixtures into **Atlas** for two tenants (`TENANT_ALPHA`, `TENANT_BETA`). Scoping by `tenantId: {$in: EVAL_TENANTS}` is described in-file as "the entire safety mechanism." Not files — DB rows.
- **Markdown from facts**: `packages/knowledge/dossier.ts` `composeDossier()` genuinely emits markdown (`# Anchor`, `## category`, `- fact text`, token-budgeted to ~600 tokens, oldest dropped first). But it is stored as a `content` **string in the `dossiers` Mongo collection**, refreshed by `refreshDossier` on review. Nothing writes it to disk, and — notably — **nothing reads `dossier.content` either**: `list-briefs.ts` uses the `dossiers` collection purely as an *index* ("whom is it worth briefing, freshest first") and then re-reads the underlying facts, because `composeDossier` drops the fact ids a receipt needs. The rendered markdown is currently dead weight.
- **No eve sandbox, no skills, no workspace materialization.** `grep sandbox|defineSkill|skills/` over `apps/app` and `packages/knowledge` returns nothing. The agent has two tools and one instruction file.
- The only real filesystem materialization is eve's own dev infrastructure: `apps/app/.eve/dev-runtime/snapshots/&lt;id&gt;/source/**` holds three full copies of the monorepo source tree, pointed at by `.eve/dev-runtime/current.json`. Build tooling, not product.
